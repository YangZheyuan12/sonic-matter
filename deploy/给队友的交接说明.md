## 1. 我们这一轮做了什么

### 1.1 部署形态：一个进程、一个端口（8080）

- 设 `SERVE_WEB=1` 后，后端用 `express.static` 直接托管前端构建产物 → 前端和 API **天然同源**。
  - 所以**不需要**装 Nginx、不需要反向代理、不需要配 CORS。
- 只用 **8080**，不用 80/443：大陆服务器上域名解析到大陆 IP 且用 80/443 提供服务要先 ICP 备案（3–20 个工作日），10/9 提交来不及；而且 80 已经被你的 Nginx 占着，我们不去抢。
- 全部是**新增**：`/opt/sonic-matter`（约 130 MB）+ 一个 systemd 单元 `sonic-matter`。
  宝塔、你的 Nginx（80/888）、MySQL、`/root/ZhiXingChuangJing-platform`、SSH 配置、`/etc` 下其它文件，一个都不改。

### 1.2 云端工程（新功能）：`/api/projects`

给用户的体验是"把工程存到服务器 + 生成分享链接 `?p=<id>`"。技术上有三点想让你知道：

- **不用 MySQL**：用 Node 24 自带的 `node:sqlite`，数据就是**一个文件** `projects.db`。所以你的 MySQL 现在什么状态都不影响我们，不用为这个动任何东西。
- **数据目录拆成两个**：
  | 目录 | 内容 | 是否公开 |
  | --- | --- | --- |
  | `generated/` | 访客导出的音频等 | **公开**（`express.static` 直接托管） |
  | `projects/` | `projects.db`（云端工程库） | **不公开**，刻意放在静态目录之外，否则数据库会被人直接下载 |
- **没有账号密码**：Demo 级实现。读取是公开的（分享链接本身就是读）；写入/删除只校验浏览器本地生成的随机身份串（作为 HTTP 请求头发来，**不放在 URL 里**——服务器的请求 URL 会进 journald 日志，放 URL 里等于把身份串漏进日志）。

### 1.3 服务怎么跑（会写进 systemd 单元的几句）

- Node 24 用**官方压缩包解压到 `/opt/sonic-matter/node`**，不装系统包、不写 `/usr`、`dnf` 一次都不用。
- Node 24 能原生跑 TypeScript 入口，**生产环境不需要 tsx / 不需要构建**，`npm ci --omit=dev` 就够（只有 5 个依赖）。
- `MemoryMax=512M`：**内存超限只会杀掉我们这个服务**，不会波及你的 MySQL / 宝塔 / Nginx；`Restart=always`（崩了自动拉起）；开机自启。
- 日志走 systemd journal，可以 `journalctl -u sonic-matter` 看，也可以限制体积（见操作手册）。

### 1.4 我们做过的验证（都在本机 8080 的真实生产构建上跑）

| 项 | 结果 |
| --- | --- |
| `npm run verify`（typecheck + lint + 单测 + 构建） | 通过：oxlint 0 警告、**server 64 例**、**web 119 例** |
| 生产模式 curl（`SERVE_WEB=1 PORT=8080`） | `/` 200 HTML、`/assets/*.js` 200、`/?p=abc123` 200、`/api/health` 200、`/nope.js` 404 错误信封 |
| 浏览器探针（headless Chrome 打开 8080） | 构建产物挂载、四个页签渲染、脚本同源、`fetch('/api/health')` 200、`?p=` 深链不白屏、**0 未捕获异常** |
| 云端工程端到端（真点按钮） | **20/20**：保存 → 列表 → 再保存走更新（revision 2）→ 清掉本地存储后打开分享链接能载入 → 新访客改别人的工程被 403 拒绝（中文提示） |
| 失效分享链接兜底 | **3/3**：不白屏，提示"这个云端工程不存在，可能已被删除，或者链接不完整。" |

### 1.5 占用（你可能会关心的）

约 130 MB 磁盘（Node 100 MB + 依赖 20 MB + 前端产物 0.5 MB）；空跑内存 100 MB 量级且被 `MemoryMax=512M` 封顶；只用 8080 一个端口；访客的音频导出在你服务器上不占 CPU（在访客浏览器本地算）。

## 2. 接下来你要做的

**前 3 步不需要等我们任何东西，今天就能做完**（第 ③ 步最费时间，建议先起）。

### ① 系统防火墙放行 8080

```bash
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
sudo firewall-cmd --list-ports        # 输出里应能看到 8080/tcp
```

只**追加**一条端口规则，不动你已有的规则。（你习惯用宝塔面板的话：面板 →「安全」→ 加一条 `TCP 8080` 也一样。）

### ② 阿里云控制台安全组放行 8080

控制台 → 云服务器 ECS → 这台实例 → **安全组** → 配置规则 → **入方向** → 手动添加：协议 `TCP`、端口 `8080/8080`、授权对象 `0.0.0.0/0`。

> ① 和 ② 是**两层**，缺任何一个，外面都打不开。

### ③ 装 Node 24（官方包解压，不用 dnf）

```bash
curl -fsSL -o /tmp/node24.tar.gz https://npmmirror.com/mirrors/node/v24.20.0/node-v24.20.0-linux-x64.tar.gz
mkdir -p /opt/sonic-matter
tar -xzf /tmp/node24.tar.gz -C /opt/sonic-matter
mv /opt/sonic-matter/node-v24.20.0-linux-x64 /opt/sonic-matter/node
/opt/sonic-matter/node/bin/node -v        # 期望输出 v24.20.0
```

### ④ 部署（等我把前端产物包发给你，5 分钟）

代码在 `main` 上，**直接在服务器上 clone 你自己的仓库**就行，不用等我们打包上传源码：

```bash
git clone --depth 1 -b main https://github.com/YangZheyuan12/sonic-matter.git /tmp/sm-src
cp -r /tmp/sm-src/server /opt/sonic-matter/
mkdir -p /opt/sonic-matter/deploy && cp /tmp/sm-src/deploy/sonic-matter.service /opt/sonic-matter/deploy/
rm -rf /tmp/sm-src

# 前端产物不在仓库里（dist 是构建产物，不入库），用我发你的 sm-dist.tgz（不到 1 MB）
mkdir -p /opt/sonic-matter/web && tar -xzf /tmp/sm-dist.tgz -C /opt/sonic-matter/web

cd /opt/sonic-matter/server
/opt/sonic-matter/node/bin/npm ci --registry=https://registry.npmmirror.com --omit=dev
cp .env.example .env
sed -i 's/^PORT=.*/PORT=8080/; s/^SERVE_WEB=.*/SERVE_WEB=1/; s#^WEB_DIST_DIR=.*#WEB_DIST_DIR=/opt/sonic-matter/web/dist#; s#^DATA_DIR=.*#DATA_DIR=/opt/sonic-matter/server/generated#' .env
chmod 600 .env          # 里面不放任何 API Key

cp /opt/sonic-matter/deploy/sonic-matter.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now sonic-matter
systemctl status sonic-matter --no-pager | head -12

curl -s http://127.0.0.1:8080/api/health ; echo    # 期望 {"ok":true,...}
curl -s http://127.0.0.1:8080/ | head -3           # 期望 HTML
```

第 ④ 步的完整版（含日常更新、排错、HTTPS 兜底）在 [`deploy/队友服务器操作步骤.md`](%E9%98%9F%E5%8F%8B%E6%9C%8D%E5%8A%A1%E5%99%A8%E6%93%8D%E4%BD%9C%E6%AD%A5%E9%AA%A4.md)。

## 5. 如果你不放心

- **不想上线就直接说"不行"**，我们改成本机演示 + 录屏，不影响提交，也不会再提这件事。
- 随时**一键卸载**（30 秒，你的服务器回到现在的样子）：

```bash
systemctl disable --now sonic-matter
rm -f /etc/systemd/system/sonic-matter.service && systemctl daemon-reload && systemctl reset-failed sonic-matter 2>/dev/null
rm -rf /opt/sonic-matter
firewall-cmd --permanent --remove-port=8080/tcp && firewall-cmd --reload
```

阿里云安全组里那条 8080 规则去控制台删掉即可。我们没在别的地方留任何东西。

- 唯一的系统级新增文件是 `/etc/systemd/system/sonic-matter.service`，**全文 44 行**，在 [`deploy/sonic-matter.service`](sonic-matter.service) 里放着，先审再装都行。
