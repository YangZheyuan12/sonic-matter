## 0. 30 秒版

我们要把你的服务器当成一个**静态站点 + 一个 Node 小服务**的宿主，跑在 **8080** 端口：

- **新增**（全部是新增，不改存量）：一个目录 `/opt/sonic-matter`（约 130 MB）、一个 systemd 服务 `sonic-matter`、监听 8080、以及一个数据目录。
- **不动**：宝塔面板、你的 Nginx（80 / 888）、MySQL、`/root/ZhiXingChuangJing-platform`、防火墙里已有的规则、`/etc` 下除了新增这一个 systemd 单元之外的所有文件。
- **需要你做的只有两件**：① 系统防火墙放行 `8080/tcp`；② 阿里云控制台安全组放行 `8080`。
- **不想要了**：第 7 节有一条命令，30 秒删干净，你的环境回到现在的样子。

如果看完觉得不合适，直接说"不行"我们就换方案（本机演示 + 录屏），不影响提交。

## 3. 需要你做的（只有两件）

### ① 系统防火墙放行 8080

```bash
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
sudo firewall-cmd --list-ports        # 确认输出里有 8080/tcp
```

这条命令**只追加**一条端口规则，不会动你已有的规则。如果你更习惯用宝塔面板管理防火墙（面板 →「安全」），在面板里加一条 `TCP 8080` 也一样。

### ② 阿里云控制台放行 8080

阿里云控制台 → 云服务器 ECS → 找到这台实例 → **安全组** → 配置规则 → **入方向** → 手动添加：

| 项 | 值 |
| --- | --- |
| 协议类型 | 自定义 TCP |
| 端口范围 | `8080/8080` |
| 授权对象 | `0.0.0.0/0`（对所有人开放；也可以先只填你的/我的 IP 做测试） |
| 备注 | `sonic-matter demo` |

> 这两层是**与关系**，缺一层外网都打不开。所以 ① 和 ② 都要做。
> 如果你有顾虑，可以先只填我们几个人的 IP，等演示完再放开——功能完全一样。

### 可选：如果你想确认端口没被别的东西占用

```bash
sudo ss -lntp | grep :8080 || echo "8080 空闲"
```

## 4. 完整执行清单（你可以自己跑，也可以让我们跑时你在旁边看）

> 前提：我们的代码已经在本地构建好并打成两个压缩包（`sm-src.tgz` = 源码、`sm-dist.tgz` = 前端产物）。

```bash
# ① 安装 Node 24（官方包解压，不用 dnf）
curl -fsSL -o /tmp/node24.tar.gz https://npmmirror.com/mirrors/node/v24.20.0/node-v24.20.0-linux-x64.tar.gz
mkdir -p /opt/sonic-matter
tar -xzf /tmp/node24.tar.gz -C /opt/sonic-matter
mv /opt/sonic-matter/node-v24.20.0-linux-x64 /opt/sonic-matter/node
/opt/sonic-matter/node/bin/node -v        # 期望 v24.20.0

# ② 解压我们的代码与前端产物（压缩包由我们上传到 /tmp）
tar -xzf /tmp/sm-src.tgz -C /opt/sonic-matter
mkdir -p /opt/sonic-matter/web && tar -xzf /tmp/sm-dist.tgz -C /opt/sonic-matter/web

# ③ 安装后端依赖（5 个依赖，走国内镜像；不装 devDependencies）
cd /opt/sonic-matter/server
/opt/sonic-matter/node/bin/npm ci --registry=https://registry.npmmirror.com --omit=dev

# ④ 写配置（把四条路径/端口改好，权限收紧）
cp .env.example .env
sed -i 's/^PORT=.*/PORT=8080/; s/^SERVE_WEB=.*/SERVE_WEB=1/; s#^WEB_DIST_DIR=.*#WEB_DIST_DIR=/opt/sonic-matter/web/dist#; s#^DATA_DIR=.*#DATA_DIR=/opt/sonic-matter/server/generated#' .env
chmod 600 .env

# ⑤ 装成 systemd 服务并启动
cp /opt/sonic-matter/deploy/sonic-matter.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now sonic-matter
systemctl status sonic-matter --no-pager      # 期望 active (running)

# ⑥ 防火墙放行（= 第 3 节 ①）
firewall-cmd --permanent --add-port=8080/tcp && firewall-cmd --reload

# ⑦ 服务器内自测
curl -s http://127.0.0.1:8080/api/health ; echo     # 期望 {"ok":true,...}
curl -s http://127.0.0.1:8080/ | head -3            # 期望 HTML
```

做完 ⑦ 之后的下一步，是在**服务器外面**用浏览器打开 `http://<你的公网IP>:8080/`。

### 以后更新代码

- **只改了前端**：我们重传 `web/dist` 即可，**不用重启服务**（静态文件是按请求从磁盘读的）。
- **改了后端**：重传源码 + `systemctl restart sonic-matter`。

## 5. 会占用你多少资源 / 会不会拖慢你

| 维度 | 实际情况 |
| --- | --- |
| CPU | 现在 load 已经接近 0；我们的服务在没人访问时几乎不占 CPU，被访问时主要是"把磁盘上的静态文件发出去" |
| 内存 | 单元里写了 `MemoryMax=512M`：**超过 512 MB 只会杀掉我们这个服务**，绝不会波及你的 MySQL / 宝塔 / Nginx。实测空跑占用在 100 MB 量级 |
| 磁盘 | 约 130 MB（Node 100 MB + 依赖 20 MB + 前端 0.5 MB）；运行数据写在 `generated/`，可以随时清 |
| 带宽 | 首次打开页面下载约 500 KB（gzip 后约 160 KB）；**音频导出在访客浏览器本地完成，不经过你的服务器** |
| 端口 | 只用 8080；与你的 80 / 888 / 3306 完全不重叠 |
| 开机自启 | 会（`systemctl enable`），不想要就在第 7 节里一起删掉 |
| 日志 | 走 systemd journal，可以用 `journalctl -u sonic-matter --vacuum-time=7d` 限制体积 |

## 6. 为什么用 8080 而不是 80

大陆的服务器上，**域名解析到大陆 IP 且用 80/443 提供服务需要先做 ICP 备案**（通常 3–20 个工作日），我们 10/9 就要提交，来不及。而**用 IP + 高位端口（8080）访问不需要备案**，所以选了 8080。

另外 80 已经被你的 Nginx 占着，我们也不应该去抢。

> 所以提交材料里会是 `http://<公网IP>:8080/` 这种形式：能直接访问，但浏览器地址栏可能提示"不安全"（因为是 http、没有证书）。如果需要一个 `https://` 链接，我们可以额外用 Cloudflare 的免费隧道（不需要域名、不需要备案）挂一个 `https://xxx.trycloudflare.com` 地址，那是**只出网、不改你任何配置**的临时方案。

**如果你更希望"用你自己的 Nginx 反代到 80 端口"**（比如你想统一管证书），也可以：我们只要把上游指向 `127.0.0.1:8080`，Nginx 那边加一个 `location /` 就行——但这需要你改自己的 Nginx 配置，我们不会替你改。默认方案不需要你做这件事。

## 7. 怎么停掉 / 完全卸载（随时，30 秒）

```bash
# 停掉并禁止自启
systemctl disable --now sonic-matter

# 删掉 systemd 单元
rm -f /etc/systemd/system/sonic-matter.service
systemctl daemon-reload
systemctl reset-failed sonic-matter 2>/dev/null

# 删掉我们新增的目录（代码、Node、数据都在这里）
rm -rf /opt/sonic-matter

# 撤掉防火墙里那条 8080 规则
firewall-cmd --permanent --remove-port=8080/tcp && firewall-cmd --reload
```

阿里云安全组里那条 8080 规则去控制台删掉即可。

**做完这些，你的服务器就回到现在的状态**（我们没在别的地方留任何东西）。

## 8. 附：唯一的系统级新增文件全文（`/etc/systemd/system/sonic-matter.service`）

请审阅，就这么长，没有别的隐藏配置。（下面这段是从仓库里的 `deploy/sonic-matter.service` 原文复制的，两份逐字一致，改的时候一起改。）

```ini
[Unit]
Description=Sonic Matter (前端 + API 单端口服务)
Documentation=file:/opt/sonic-matter/deploy/README.md
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/sonic-matter/server

# 密钥等敏感配置只放在这个文件里（chmod 600，永不入库）。
# 前缀 "-" 表示文件不存在时也继续启动（此时走本地 fallback，功能仍可用）。
EnvironmentFile=-/opt/sonic-matter/server/.env

# 部署参数：为清晰起见这里显式写一遍，同时请让 deploy/README.md 里的 .env 保持一致
# （systemd 中 EnvironmentFile 的优先级高于 Environment=，两边写成同一个值最省心）。
Environment=NODE_ENV=production
Environment=PORT=8080
Environment=SERVE_WEB=1
Environment=WEB_DIST_DIR=/opt/sonic-matter/web/dist
Environment=DATA_DIR=/opt/sonic-matter/server/generated

# 直接用 Node 24 运行 TypeScript 入口（原生类型剥离），生产环境不需要 tsx。
ExecStart=/opt/sonic-matter/node/bin/node /opt/sonic-matter/server/src/index.ts

Restart=always
RestartSec=3

# 内存保险：超限只杀本服务，不会波及同机上的宝塔 / MySQL 等其它进程。
MemoryMax=512M

# 最小加固；若启动失败先逐行注释掉排查。
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=true

# 日志走 journald：journalctl -u sonic-matter -f
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

（`ProtectSystem=full` 只让 `/usr`、`/boot`、`/etc` 对**我们这个进程**只读，不影响你系统本身。）

## 9. 常见问题

**Q：会不会和我的宝塔 / Nginx 冲突？**
A：不会。端口不重叠（我们 8080，你 Nginx 80/888），我们不读写任何 Nginx 配置，不改站点、不申请证书。

**Q：会不会影响我的 MySQL？**
A：不会。不碰 3306、不建库、不改用户；内存上还有 `MemoryMax=512M` 兜底。

**Q：公网暴露一个没有鉴权的服务，会不会给我惹麻烦？**
A：这是唯一的真实风险点。当前后端是 Demo 定位：**没有登录、没有限流**，任何知道地址的人都能调用接口（比如触发一次 AI 生成）。我们的应对是**服务器上不放我们的 API Key**——访客要用 AI 功能得在页面「设置」里填自己的 Key，所以不会消耗任何人的额度（也没配 Key 时自动走本地 fallback，功能仍可演示）。
如果你仍有顾虑，我们能加两种零依赖的简单防护：① 只允许白名单 IP 访问；② 加一个每分钟 N 次的限流。你说要哪种我们就加。

**Q：会不会被搜索引擎收录 / 被人扫到？**
A：IP + 非标准端口基本不会被爬虫主动发现；被扫到也只会看到这个 Demo 页面。演示结束后你可以按第 7 节卸掉。

**Q：数据存在哪？我能备份吗？**
A：`/opt/sonic-matter/server/generated/`（访客导出的音频、云端工程 `projects.db`）。直接 `tar` 打包这个目录就是完整备份；删掉它就是清空数据。

**Q：需要备案吗？**
A：用 `IP:8080` 不需要。只有"域名解析到大陆服务器 + 用 80/443"才需要备案。

**Q：你能自己在服务器上操作吗？**
A：不会。我们有约定：**不使用任何服务器凭据、不代你执行远程命令**。所有命令都由你在服务器上（或你授权的人）执行；我们可以把命令一条条准备好、出错时帮你看报错。

## 10. 出问题怎么办

1. **服务起不来**：`systemctl status sonic-matter --no-pager` 和 `journalctl -u sonic-matter -n 100 --no-pager`，把输出发给我们。
2. **服务正常但外面打不开**：九成是第 3 节那两层放行漏了一层（`firewall-cmd --list-ports` 和阿里云安全组各查一次）。
3. **想立刻停止对外服务**：`systemctl stop sonic-matter`（立刻断开，稍后想恢复就 `systemctl start sonic-matter`）。
4. **想彻底不管了**：直接走第 7 节。
