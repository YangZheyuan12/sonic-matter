# Audio Director Agent 威胁模型与安全边界

本文记录 Agent 工程编辑链路的资产、信任边界、主要威胁、已实施控制和已知限制。目标不是宣称“绝对安全”，而是让每项安全结论都能对应到代码和回归测试。

## 1. 保护目标

需要保护的资产包括：

- 用户的源工程和待审批候选工程；
- Agent API Key、Authorization、Cookie、Token、密码和服务器环境变量；
- 服务器文件系统、Shell、内网服务与云元数据接口；
- Agent Run Trace、SQLite 数据库和日志；
- 工具步骤、执行时间、修订轮数和供应商调用成本等资源预算。

核心安全不变量：

1. 用户指令只是数据，不能改变系统规则、工具白名单和人工审批要求。
2. Planner 只生成计划；只有注册表中的工具能够执行。
3. 工具参数必须先通过严格 Schema，未知字段和超限数组不能进入业务逻辑。
4. 用户批准前只修改候选快照，不能覆盖源工程。
5. 规划、执行和修订都有确定上限，失败或取消后不能继续启动新工具。
6. 日志、Trace、数据库和错误响应不能保存或返回凭据明文。

## 2. 信任边界

```text
不可信浏览器输入
  │  身份、同源、JSON、Zod 校验
  ▼
Agent Run HTTP API
  │  指令安全预检 + 客户端模型地址 SSRF 检查
  ▼
Planner / 外部模型供应商（不可信输出）
  │  Structured Output + AgentPlan Schema + 工具名复查
  ▼
Tool Registry（唯一执行边界）
  │  每个工具独立输入/输出 Schema + AbortSignal
  ▼
候选 Project ── Deterministic Evaluator ── 人工批准 ── 正式工程
  │
  └── 脱敏后的 Trace / SQLite / 日志
```

浏览器输入、模型输出和工具返回值都按不可信数据处理。生产注册表只暴露六个工程工具：

- `inspect_project`
- `add_track`
- `update_track`
- `remove_track`
- `replace_track_notes`
- `validate_project`

注册表没有文件、Shell、进程、HTTP、任意网络或密钥读取工具。

## 3. 威胁与控制

| 威胁 | 可能后果 | 主要控制 | 安全失败结果 |
| --- | --- | --- | --- |
| Prompt Injection 要求忽略规则或绕过审批 | 越权计划、跳过人工确认 | 指令预检；系统提示把用户文本标为不可信；候选工程必须进入 `awaiting_approval` | `unsafe_instruction`，不调用供应商和工具 |
| 要求执行 Shell、读取 `.env` 或泄露凭据 | 文件、环境变量或系统权限泄漏 | 指令预检；生产注册表无对应能力；未知工具二次拒绝 | 不生成可执行计划 |
| 模型伪造未知工具 | 绕过业务工具边界 | JSON Schema 只枚举注册工具；服务端再次调用 `registry.get`；Runner 再次通过注册表执行 | `unknown_planned_tool` 或 `unknown_tool` |
| 工具参数夹带 `command` 等未知字段 | 参数注入 | Zod `.strict()`；工具执行前校验输入和输出 | `invalid_tool_input`，业务函数不执行 |
| 超长音符、轨道或执行参数 | 内存和 CPU 耗尽 | 指令 500 字符；参数 JSON 8,000 字符；每轨 4,096 音符；工程 32 轨；计划 8 步 | 输入或计划校验失败 |
| 无限工具循环或无限自我修订 | 成本、延迟失控 | 计划最多 8 步；Runner 步骤预算；最多 2 轮修订；重复计划无进展检测 | `step_budget_exceeded`、`revision_limit_reached` 或 `revision_made_no_progress` |
| Planner 供应商永久挂起 | Run 永远停在 planning | 独立 45 秒规划截止时间；AbortSignal；超时竞速不继续等待不合作的适配器 | `planner_timeout`，Run 进入 `failed` |
| 工具超时或用户取消 | 后续步骤在错误状态继续执行 | Runner 总超时；每步前检查信号；注册表将取消传播到工具；终态状态机 | `runner_timeout` 或 `canceled`，不启动下一步 |
| 中间工具成功、后续工具失败 | 部分修改被误当成正式结果 | 修改只发生在候选快照；失败 Trace 记录部分结果；没有批准就不能应用 | Run 进入 `failed`，源工程不变 |
| 客户端模型地址指向 localhost、内网或元数据地址 | SSRF、读取内部服务 | 客户端自定义地址必须为公开 HTTPS；拒绝 URL 凭据、环回、私网、链路本地和常见元数据主机 | HTTP 400，不创建 Run、不发网络请求 |
| 日志或 Trace 包含 Key、Token、Cookie、私钥 | 凭据持久化泄漏 | 结构化字段名脱敏；自由文本赋值脱敏；Key/Bearer/PEM 模式脱敏；Trace 写入和读取双重清理 | 只保存 `***` 和必要长度信息 |

## 4. 资源预算

当前第一阶段预算如下：

| 资源 | 上限 |
| --- | ---: |
| 用户指令 | 500 字符 |
| 单次计划步骤 | 8 |
| 单步动态参数 JSON | 8,000 字符 |
| Run Trace 步骤 | 32 |
| 单轨音符 | 4,096 |
| 工程轨道 | 32 |
| 自动修订 | 2 轮 |
| Planner 截止时间 | 45 秒 |
| Runner 默认总超时 | 90 秒 |

这些值是安全默认值，不是永久产品规则。若 Eval 显示合法任务经常触顶，应根据失败分布调整，不能直接删除上限。

## 5. 敏感数据处理

以下内容不得进入日志、Trace、数据库查询结果或错误响应：

- `apiKey`、`Authorization`、Bearer Token；
- Access Token、Refresh Token、Cookie、密码；
- `sk-...`、`xi-api-key=...` 等常见密钥形态；
- PEM 私钥正文。

脱敏在两个位置执行：

1. `logger.ts` 在日志输出前处理结构化字段和自由文本。
2. `runStore.ts` 在 Trace 写入与读取时都执行清理，防止旧数据或手工写入的数据从查询接口返回。

错误响应只返回稳定错误码和通用中文信息，不回显供应商原文、用户提交的目标地址或模型密钥。

## 6. 安全演练与回归测试

运行完整验证：

```powershell
npm run verify
```

与 Agent 安全直接相关的回归测试覆盖：

- 中英文规则绕过、Shell、凭据读取和任意网络请求；
- Planner 输出不存在的工具；
- 命令字段注入和 4,097 个音符的超限数组；
- 8 步计划上限、Runner 步骤预算和两轮修订上限；
- 执行前取消、执行中取消、工具总超时和 Planner 永久挂起；
- 部分成功后立即停止，不执行后续工具；
- 日志、Trace、SQLite 和查询结果的密钥脱敏；
- localhost、私网 IP、链路本地 IP、云元数据地址和 URL 内嵌凭据。

固定离线 Eval 中的两个恶意案例还会检查安全拒绝、零越权工具调用、源快照不变和无敏感输出。

## 7. 已知限制

1. **指令预检不是完整的 Prompt Injection 检测。** 正则可以拦截明确越权要求，但可能被隐喻、编码或多语言变体绕过。真正的权限边界仍是工具白名单、严格参数 Schema、步骤预算和人工审批。
2. **客户端模型地址检查不能单独消除 DNS Rebinding。** 当前会拒绝显式本机、私网、链路本地和元数据地址，但域名可能在解析后指向私网。生产部署仍应使用出站防火墙、代理允许名单或固定供应商域名。
3. **AbortSignal 不能强制终止不合作的第三方代码。** 规划截止时间会让 Run 停止等待并进入失败状态；底层适配器仍应正确响应取消，生产 OpenAI SDK 已配置自身超时。
4. **Run 数据库不是通用秘密仓库。** 它会脱敏常见凭据，但不应把密钥或完整敏感 Prompt 主动写入 Trace。数据库文件仍需依赖服务器文件权限和备份策略保护。
5. **恶意音乐内容不是本阶段目标。** 当前安全策略关注系统权限、凭据、资源和工程完整性，不进行版权、内容合规或音频听感审核。
6. **公开 HTTPS 自定义供应商仍属于外部信任域。** 用户配置供应商时，指令会发送给该服务；界面和部署文档应明确提示只使用可信服务。

## 8. 事件排查顺序

出现安全相关失败时，按以下顺序检查：

1. 用 Run ID 和 requestId 定位脱敏后的 Trace 与日志。
2. 确认失败发生在指令预检、Planner、工具输入校验、Runner 还是 Evaluator。
3. 检查是否调用了白名单外工具；正常结果应为零次。
4. 检查源工程是否保持不变，以及候选工程是否从未被批准。
5. 将可复现输入加入安全回归测试和固定 Eval，再修改策略或工具。
6. 若怀疑凭据泄漏，先吊销凭据，再处理日志和数据库保留数据。
