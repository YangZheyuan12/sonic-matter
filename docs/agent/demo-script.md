# Audio Director Agent：2–3 分钟演示稿

目标时长约 2 分 40 秒。演示前启动前后端并打开音乐工作室；没有真实模型配置时使用本地模式，控制流程、审批和离线 Eval 仍可完整演示。

## 0:00–0:20｜先说清问题

**操作**：打开工作室中的现有多轨工程。

**讲解**：“Sonic / Matter 不让模型直接交付一段不可修改的音频。Audio Director Agent 接收自然语言，但结果仍然是轨道和音符组成的可编辑 Project；每一步可追踪、可验收，最后由人决定是否写入。”

## 0:20–0:55｜跑一次直接成功

**操作**：输入“添加一条低沉的大提琴轨道”，启动 Agent Run；展开 Trace。

**讲解**：“指令先经过安全检查，再由 Planner 选择白名单工具。这里能看到 `add_track` 的执行记录。验证通过后状态是 `awaiting_approval`，注意它还没有改动当前工程。”

**核对证据**：Trace 有计划、Tool Call 和 Evaluation；Review 面板能看到源工程与候选工程差异。

## 0:55–1:25｜讲自动修订

**操作**：切到案例文档中的 `modify-02-change-instrument`，展示 Eval 报告对应行或预先准备的 Trace。

**讲解**：“第一次只检查工程，没有完成乐器替换。Evaluator 明确指出 Cello 约束未满足，Revision 才追加 `update_track` 并重新验证。这个案例是 2 次工具调用、1 次修订、65 ms 逻辑耗时。系统靠反馈闭环纠错，但最多只在预算内修订，不会无限重试。”

## 1:25–1:55｜批准与拒绝都可控

**操作**：回到 Review，先展示差异，再点击批准；若时间允许，再跑一次并点击拒绝。

**讲解**：“批准后候选工程才进入前端 History，因此可以撤销。拒绝则进入 `canceled`，当前工程保持不变。验证通过和真正应用，是两件分开的事。”

## 1:55–2:20｜展示安全失败

**操作**：打开 `adversarial-01-tool-injection` 或输入要求绕过审批、调用系统命令的指令。

**讲解**：“危险输入在工具执行前被拒绝：工具调用为 0、源快照不变、也没有敏感输出。冲突约束同样明确失败。这里的正确行为不是强行生成，而是安全、可解释地停下来。”

## 2:20–2:40｜用数字收尾

**操作**：展示 README 自动指标区块和 Eval 报告；指出复现命令。

```powershell
npm run eval:agent
```

**讲解**：“当前固定离线基线是 20 个案例，覆盖创建、修改、约束、冲突和注入。数字由这条命令同时写入 README、Markdown 报告和 JSON，不靠手工抄写。离线满分证明控制流程可重复，不代表任意真实模型输入都完美。”

## 现场故障备用路径

- 真实模型不可用：切换本地模式，继续展示 Run、Trace、Review 与审批。
- 网络不稳定：直接打开已提交的 Eval 报告与三个案例，运行离线 `npm run eval:agent`。
- 时间不足：保留“直接成功 → 自动修订证据 → 安全失败 → 指标来源”四段，跳过第二次拒绝操作。
